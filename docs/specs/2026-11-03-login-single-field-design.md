# 登录页只留一个输入框：打字找人，找不到就是新人

2026-11-03 · 状态：待批准 · 规模：小改动（只动登录页扩展与它的译文）

## 1. 为什么

现在的登录页有两套入口：GNOME 自带的竖排用户列表（点名字登录），和底部的 “Add person”（换成 “School email”
输入框，给新人用）。推车式的笔记本一台有几十个学生，列表又长又暴露所有人的名字；个人笔记本上 “Add person”
又是多余的一步。

用户裁定（2026-11-03）：

- 不分人数，登录页**永远只有一个输入框**，一个人也是打字进。打一两个字母就该找到自己。
- 不打字时一个名字都不显示；打字后，匹配的人**直接显示在输入框下面**。
- 底部的 “Add person” 去掉；新人就在这个框里输入自己的学校邮箱，不要 “+” 之类的额外操作。
- 实现走方案 A：就用 GNOME 原有的用户名输入框，在它下面加匹配列表（见第 4 节）。

## 2. 目标、非目标、反目标

**目标**

- 开机、注销、登录失败、卡片取消之后，登录页都是同一个样子：头像占位、一个输入框、框下的 “Local manager”。
- 本机已有的人：打字 → 框下出现匹配的人 → 回车或点击 → 和以前点列表里的名字完全一样地开始登录。
- 新人：输入完整学校邮箱 → 回车 → 学校登录卡片（今天 “Add person” 那条路，不变）。
- 键盘能完成全部操作：上下键选人，回车登录，Esc 收起列表。

**非目标**

- 不改锁屏（解锁对话框只有当前用户，本来就没有列表）。
- 不改学校登录卡片、访客、Apps、关机、Local manager 的行为。
- 不做 “很久没登录的人自动收起/清理”：要另行设计。

**反目标**（做出来就算失败）

- 不打字时屏幕上出现任何人的名字。
- 打了几个字母再回车，被当成用户名 “d” 之类去登录（GNOME 原本的行为），而不是选中框下的那个人。
- 输入密码、验证码时读取或挂钩输入框（现有 `_isSecret` 的规矩不变）。

## 3. 行为细节

- **谁能被找到**：AccountsService 里的普通用户，排除 `guest`、`kiosk-*`、`itadmin`（它们各有入口），与今天列表的过滤一致。
- **怎么匹配**：不分大小写，匹配显示名里任一词的开头，或用户名（学校账号就是邮箱）的开头。
  泰文、中文等不按空格分词的名字，也接受显示名中间的子串。
- **怎么排**：最近登录的在前（AccountsService 的 login time）；最多显示 5 个，多出的不显示，
  最后一行提示 “继续输入以缩小范围”。
- **每一行**：小头像（有照片用照片，没有用默认头像）、显示名、用户名（灰字）。
- **回车**：
  - 框下有匹配时，第一个默认选中，回车就是登录这个人；
  - 输入里带 `@` 时，不默认选中任何人（可能是要输入新的邮箱），回车按输入的文字登录，除非用上下键明确选了某人；
  - 没有任何匹配时，回车按输入的文字登录：新的学校邮箱打开学校卡片，本地账号名照旧要密码。
- **学校域名补全**（2026-11-05 改）：一开始打名字就在同一个列表里、匹配的人之后，给出 “名字@域名”（每个允许的域名一行，最多 5 行）；
  打了 `@` 之后只给以 `@` 后面已打的部分开头的域名，地址打全了就不再给。名字里有邮箱本地部分不能有的字符（空格、非 ASCII 等）、
  没有域名或输入为空时不给。域名行从不默认选中；用上下键选中后回车、或点它，只把整个地址填进输入框，再回车才登录。
  已经作为某人列出的地址不重复给。（原先只在输入以单个 `@` 结尾时另弹一个 PopupMenu，它会抢键盘，已去掉。）
- **返回箭头**：用户名这一步没有可以回去的列表，隐藏；密码这一步的返回键回到空输入框。
- **提示文字**：“School email” 改为 “Name or school email”，所有语言重新翻译；“Add person” 这条译文删除。

## 4. 方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| **A（选定）** | 用 GNOME 的用户名输入框；永远停在 “输入用户名” 这一步，不显示用户列表；框下用一个普通列表（不是 `PopupMenu`：弹出菜单会抢走键盘，打字就断）列出匹配；拦截回车，选中某人时改走 `_signInAs` | 新人、域名弹出、学校卡片都已挂在这个框上，界面只有一个框；回车拦截依赖 GNOME 50 内部，扩展本来就锁版本 |
| B | 自己做一个搜索框和结果列表，GNOME 的输入框只在幕后用 | 外观完全可控；两个输入框要同步状态（切 VT、密码错、卡片取消都要复位），代码多两三倍 |
| C | 保留 GNOME 的列表，加一个过滤框 | 改动最小；不打字时列表仍在，违背 “不显示名字”，也做不出 “以新邮箱登录” |

## 5. 留给实施者

- 永远停在用户名一步：用 GNOME 自己的设置 `org.gnome.login-screen disable-user-list=true`（镜像的 gschema override），
  GNOME 50.1 的 `_onReset` 就走 `_hideUserListAskForUsernameAndBeginVerification`，用户名一步也自动隐藏返回键，不用打补丁。
- 回车拦截：在用户名一步、输入框不是秘密输入时，挂 `activate` 之前；拿不准时宁可按 GNOME 原样处理。
- `shelf.js` 去掉 Add person 按钮；`strings.js`、`.pot`、84 个 `.po` 同步（check-tree 第 50 条）。
- 测试：gjs 能跑的匹配与排序单独成函数并加单元测试；VM 上验证 0 人、1 人、6 人以上、带 `@`、新邮箱、本地账号、
  密码错后回到空框、切 VT 回来；截图全留。
